## Was anything copied verbatim?

**Yes, in one place, and on purpose.**

    Verbatim-copy: src/main/resources/gui

`src/main/resources/gui/` holds three HTML files — `swagger-ui.html`, `redoc.html` and
`oauth2-redirect.html` — taken from what the original serves at `GET /docs`, `GET /redoc`
and `GET /docs/oauth2-redirect`. They are the source's own shells: the same markup, the same
third-party bundles at the same CDN URLs, the same titles, with the document URL and the
title as the only substitutions. `RENDERING.md` R3 requires it — the interface that already
exists is the one the port ships — and R5 compares the result against screenshots captured
from the original running, which is only a comparison worth having because the markup is
not a rewrite. The four screens come out byte-identical; `opal-port/gui/audit-result.txt`
records the run.

Nothing else is a copy. Every Java file here was written for this port, and no fixture, test
corpus or data file was taken from the original.

## Is behaviour derived even where no text was copied?

**Yes, and that is the whole point of it.** 151 rules in
`opal-port/specs/SPEC-002-opal-complete.md` describe what `permitio/opal` does, and all but
three of them were established by running the original's own code — as a function, as a
process over HTTP, or as a whole fleet with a real OPA behind it. `opal-port/docs/question-log.md`
records each one and how it was checked. The rebuild answers the same way by design; where it
deliberately answers differently, `README.md` lists it under *Where it differs from
permitio/opal*.

## What licence that forces on this project

Apache-2.0 permits a derived work under other terms provided the notice above is kept. The
three vendored HTML shells are the original's files and carry its licence with them; the
attribution above covers them and the derived behaviour alike.

The shells themselves load Swagger UI and ReDoc from `cdn.jsdelivr.net` at run time, exactly
as the original's do. Neither bundle is redistributed here.
